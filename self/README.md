# سلف‌بات حرفه‌ای تلگرام (چندکاربره)

سلف‌بات با قابلیت‌های: ساعت فنسی، ریکت خودکار، تپچی (بنر)، افکت متن، اسپم، اکشن،
**قفل پیوی**، **آموزش نقش‌های گرگینه** + **ربات مدیریت چندکاربره**.

---

## 🐺 آموزش نقش‌های گرگینه (جدید)

توضیح کامل هر ۴۳ نقش بازی «گرگینه» (Werewolf): تیم، زمان قابلیت، تعداد استفاده،
هدف، توانایی، نکته‌ها و استراتژی.

**در سلف (هر چتی):**

| دستور | نتیجه |
|---|---|
| `آموزش نقش` | لیست کامل همه ۴۳ نقش به تفکیک تیم |
| `آموزش دردسر` | توضیح کامل نقش «دردسرساز» |
| `آموزش لیلیت` | توضیح کامل نقش «لیلیت» |
| `آموزش <نام نقش>` | توضیح هر نقشی که اسمش را بنویسید |

**در ربات مدیریت:** دکمه «🐺 نقش‌های گرگینه» از کیبورد → انتخاب تیم → انتخاب نقش →
مشاهده توضیح کامل.

---

## 🎹 منوهای کیبوردی (جدید)

منوی اصلی ربات مدیریت حالا با **دکمه‌های کیبورد پایین چت** کار می‌کند (به‌جای
اینلاین) تا تجربه کاربری بهتری داشته باشید:

- **📱 ساخت اپ و دریافت API** — راهنمای ساخت اپ (خودکار یا دستی)
- **🔐 فعال‌سازی سلف** — شروع ورود و ساخت سشن
- **🎛 پنل سلف من** — باز کردن پنل اینلاین سلف
- **📊 وضعیت من** — وضعیت فعال‌سازی و اعتبار
- **🐺 نقش‌های گرگینه** — مرور آموزشی نقش‌ها
- **👑 پنل مدیریت** (فقط مدیر اصلی) — آمار و مدیریت کاربران
- **❌ انصراف / 🏠 منوی اصلی** — لغو مرحله جاری، بازگشت به منوی اصلی

> اینلاین فقط برای **توضیحات/تأیید** استفاده می‌شود؛ منوها و مدیریت کاربر
> با کیبورد ریپلای هستند تا دسترسی سریع‌تر شود.

## 📲 ورود شماره با دکمه مخاطب (جدید)

در مرحله «فعال‌سازی سلف» یا «ساخت خودکار اپ»، دکمه **«📲 ارسال شماره من»**
کنار کیبورد قرار دارد که با یک ضربه شماره را ارسال می‌کند — بدون نیاز به تایپ.

اگر ترجیح می‌دهید خودتان تایپ کنید، این فرمت‌ها هر یک پذیرفته و خودکار به
فرمت بین‌المللی `+98912xxxxxxx` تبدیل می‌شوند:

| ورودی کاربر | تبدیل |
|---|---|
| `09123456789` | `+989123456789` |
| `9123456789` (بدون صفر) | `+989123456789` |
| `00989123456789` | `+989123456789` |
| `+989123456789` | همین‌طور |
| `98 912 345 6789` (با فاصله/خط تیره) | `+989123456789` |
| `+44791...` (غیر ایرانی) | همین‌طور (با + معتبر) |

## ۱) قفل پیوی 🔒 — حذف دوطرفه خودکار پیام‌ها

وقتی پیوی یک نفر را قفل کنید، **هر پیامی که برایتان بفرستد در کسری از ثانیه برای
هر دو طرف حذف می‌شود** (مثل حذف دستی → «حذف برای همه»؛ فقط خودکار).

### دستورات قفل

| روش | دستور |
|---|---|
| داخل پیوی خود فرد | `قفل پیوی` یا `پیوی قفل` |
| ریپلای روی پیام فرد (گروه/هرجا) | ریپلای + `قفل پیوی` |
| با یوزرنیم | `قفل پیوی @username` |
| با آیدی عددی | `قفل پیوی 123456789` |

### دستورات حذف قفل

| روش | دستور |
|---|---|
| داخل پیوی فرد یا ریپلای | `حذف پیوی قفل` یا `حذف قفل پیوی` |
| با یوزرنیم | `حذف پیوی قفل @username` |
| با آیدی عددی | `حذف قفل پیوی 123456789` |
| با شماره لیست | `حذف قفل پیوی 2` |

### مدیریت لیست

- `لیست قفل پیوی` (یا `لیست پیوی قفل`) → نمایش قفل‌شده‌ها + تعداد پیام‌های حذف‌شده
- `پاکسازی قفل پیوی` → حذف همه قفل‌ها

> پیام تایید دستور در چت طرف بعد از ۵ ثانیه خودکار پاک می‌شود تا ردی باقی نماند.
> در پنل اینلاین (`پنل`) هم بخش «🔒 قفل پیوی» اضافه شده است.

## ۲) ربات مدیریت سلف (چندکاربره) 👑

`manager_bot.py` یک ربات مستقل است که برای **چند نفر** سلف اجرا می‌کند.
مدیر اصلی (`ADMIN_ID`) تعیین می‌کند سلف هر کاربر **فعال/غیرفعال** باشد و
**چه مدت** فعال بماند.

### جریان کاربر

1. `/start` در ربات مدیریت → **کیبورد منوی اصلی** پایین چت باز می‌شود
   (اگر اد اجباری فعال باشد → عضو کانال‌ها + «✅ بررسی عضویت» + ادامه از کیبورد)
2. **«📱 ساخت اپ و دریافت API»** (کیبورد) → دو راه:
   - **🚀 ساخت خودکار**: ربات خودش به my.telegram.org وصل می‌شود و اپ را می‌سازد؛
     اگر از قبل اپ داشته باشید، همان را تحویل می‌دهد.
   - **📝 دستی**: آموزش قدم‌به‌قدم + ثبت `api_id` و `api_hash`
3. **«🔐 فعال‌سازی سلف»** (کیبورد) → دو راه ورود شماره:
   - **📲 دکمه «ارسال شماره من»** (اشتراک مخاطب با یک ضربه — فقط شماره خودتان)
   - **✏️ تایپ دستی** — هر فرمت پذیرفته و خودکار به `+98...` تبدیل می‌شود
     (`0912...` / `912...` / `0098...` / با فاصله یا خط‌تیره)
   سپس: کد تایید → (رمز دومرحله‌ای اگر دارد) → ساخت خودکار:
   - **سشن** با نام یکتا در `sessions/`
   - **`config.json`** اختصاصی در `data/<آیدی کاربر>/`
4. درخواست برای مدیر می‌رود → مدیر مدت اعتبار را انتخاب می‌کند → سلف اجرا می‌شود
5. **«🎛 پنل سلف من»** (کیبورد) → راهنما می‌دهد پنل اینلاین را از همین ربات
   در هر چت باز کنید؛ (داخل چت خودتان هم دستور `پنل` کافی است — دیگر نیازی به
   ساخت ربات جداگانه نیست)
6. **«🐺 نقش‌های گرگینه»** (کیبورد) → مرور تیم‌ها و آموزش هر نقش

> دکمه «❌ انصراف»/«🏠 منوی اصلی» روی کیبورد، هر مرحله‌ای از ورود اطلاعات را
> لغو و به منوی اصلی برمی‌گرداند. منوهای توضیحی/تأییدی هم با دکمه‌های اینلاین
> همان‌طور که لازم است پنل می‌شوند.

### پنل مدیر

- **⏳ درخواست‌های در انتظار** → تایید (با انتخاب مدت: ۱/۷/۳۰/۹۰ روز، نامحدود، دلخواه) یا رد
- **👥 لیست کاربران** → جزئیات هر کاربر: وضعیت، اعتبار، پروسه
- **📢 اد اجباری** → مدیریت عضویت اجباری (بخش بعدی)
- **⏰ تمدید اعتبار** / **🔴 غیرفعال کردن** / **🗑 حذف کاربر** (با حذف سشن و کانفیگ)
- **Watchdog**: پایان اعتبار → توقف خودکار + اطلاع به کاربر و مدیر
- **ری‌استارت خودکار**: اگر سلف کاربر کرش کرد (حداکثر ۵ بار در ساعت)

---

## ۳) اد اجباری (عضویت اجباری) 📢

مدیر می‌تواند **کانال و گروه** به‌عنوان عضویت اجباری تعریف کند؛ تا وقتی کاربر
عضو نشده (و «✅ بررسی عضویت» را نزده)، ربات برای او کار نمی‌کند.

- **افزودن**: پنل مدیریت → اد اجباری → «➕ افزودن کانال/گروه»\n
  (یوزرنیم عمومی `@channel`، آیدی عددی `-100...` یا لینک عمومی)
- **پیش‌نیاز**: ربات مدیریت باید **عضو آن کانال/گروه** باشد تا بتواند
  عضویت کاربران را چک کند (در غیر این صورت هنگام افزودن اخطار می‌دهد).
- کانال **خصوصی**: لینک دعوت را می‌گیرید تا دکمه عضویت ساخته شود
  (یا «رد کن» تا بدون لینک فقط نام نمایش داده شود).
- **گیت کاربری**: لیست کانال‌ها با دکمه لینک + دکمه «✅ بررسی عضویت»
  اینلاین؛ پس از عضویت واقعی، دکمه را می‌زند و وارد ربات می‌شود.
- **مدیر اصلی از این گیت معاف است.**
- بررسی عضویت ۶۰ ثانیه کش می‌شود تا سرعت پاسخ ربات پایین نیاید.
- اگر دسترسی ربات به کانالی قطع شود، همان کانال موقتاً نادیده گرفته می‌شود
  تا همه کاربران قفل نشوند (در کنسول اخطار چاپ می‌شود).

---

## ۴) ساخت خودکار اپ (api_id/hash) 🚀

به جای آموزش دستی my.telegram.org، دکمه **«🚀 ساخت خودکار اپ»**:

1. شماره تلگرام را می‌فرستید → کد ورود به اکانت تلگرام‌تان ارسال می‌شود
2. کد را می‌فرستید → ربات به my.telegram.org وصل می‌شود و:
   - اگر **از قبل اپ** داشته باشید → همان api_id/hash + عنوان اپ را می‌دهد
   - در غیر این صورت اپ جدید (`Self Panel <آیدی>`) می‌سازد و تحویل می‌دهد
3. مقادیر به‌صورت خودکار در پروفایل شما ثبت می‌شود.

> نکته: این قابلیت با خواندن صفحات my.telegram.org کار می‌کند؛ اگر ساختار سایت
> تغییر کند یا تلگرام محدودیت کند، پیام خطای واضح می‌گیرید و «ثبت دستی» همیشه
> به‌عنوان جایگزین باقی می‌ماند.

## ۵) پنل مشترک — بدون ربات جداگانه 🎛

از این نسخه به بعد **هر کاربر نیازی نیست برای خودش در BotFather ربات بسازد**.
ربات مدیریت (`manager_bot.py`) به‌صورت اینلاین پنل همه کاربران را سرو می‌کند.

### نحوه کار کاربر

- در ربات مدیریت: دکمه **«🎛 پنل سلف من (باز کن در چت)»** (سوییچ به اینلاین)
- یا داخل هر چتی: دستور `پنل` → سلف خودش با همین ربات مدیریت پنل را باز می‌کند

### جدایی کامل داده‌ها (بدون قاطی شدن)

- هر کلیک callback با نام‌فضای `s:<account_id>:<عملیات>` کد شده و ربات
  **فقط اگر کلیک‌کننده همان اکانت باشد** اجرا می‌کند — کسی دیگر در گروه
  روی پنل شما بزند پیام ⛔ می‌گیرد.
- متن پنل همیشه از روی **config.json خودِ همان کاربر** (خوانده‌شده به‌روز)
  رندر می‌شود؛ هیچ config در حافظه بین کاربران به اشتراک گذاشته نمی‌شود.
- تغییرات از طرف ربات روی config کاربر **اتمیک** نوشته می‌شود و
  یک «واچر همگام‌سازی» در پروسه سلف همان کاربر (هر ۲ ثانیه) تغییرات را
  اعمال می‌کند (ساعت/فونت/تپچی/بنرها/اکشن‌ها لحظه‌ای sync می‌شوند).
- اکشن‌های لحظه‌ای مثل «توقف همه اسپم‌ها» از طریق فایل
  `data/<user>/commands.json` به پروسه سلف همان کاربر می‌رسند.
- کاربری که غیرفعال/منقضی شده، در اینلاین switch_pm می‌گیرد و پنل نمی‌سازد.

### پیش‌نیاز

- در @BotFather برای ربات مدیریت **`/setinline`** را فعال کنید.
- کاربرانی که هنوز ربات اختصاصی‌دار (`menu_bottoken`) همان حالت قدیمی
  برایشان ادامه دارد و اولویت با ربات خودشان است.

### اولین کانفیگ برای مدیر

هنگام اولین اجرا، رکورد مدیر ساخته می‌شود و اگر فایل‌های تک‌کاربره‌ی قدیمی
(`config.json` و `user_session.session`) وجود داشته باشند، به عنوان
**کانفیگ و سشن مدیر** به ارث می‌رسند؛ یعنی همان تنظیمات فعلی شما حفظ می‌شود.

## اجرا

### حالت چندکاربره (پیشنهادی)

```bash
cd self
pip install -r requirements.txt
cp .env.example .env   # مقادیر را پر کنید
python manager_bot.py
```

در `.env`:

```
API_ID=...            # اپ مدیر (my.telegram.org)
API_HASH=...
MANAGER_BOT_TOKEN=... # توکن ربات مدیریت (@BotFather) — ترجیحاً ربات جداگانه
ADMIN_ID=...          # آیدی عددی مدیر اصلی (مثلاً از @userinfobot)
```

⚠️ **پیش‌نیاز پنل مشترک**: برای ربات مدیریت در @BotFather **`/setinline`**
را فعال کنید (پنل اینلاین کاربران با همین ربات کار می‌کند).

⚠️ **پیش‌نیاز اد اجباری**: ربات مدیریت را در کانال/گروه‌های موردنظر
**عضو** (ترجیحاً ادمین) کنید.

وقتی ربات بالا بیاید، در کنسول **یوزرنیم ربات مدیریت** چاپ می‌شود.
عیناً همان ربات را در تلگرام باز کنید و `/start` بفرستید.

## ❗ رفع مشکل: «ربات هیچ پنلی باز نمی‌کند»

اگر `/start` یا دکمه‌ها هیچ جوابی ندادند، به ترتیب چک کنید:

**۱) آیا پروسه‌ی ربات مدیریت اصلاً در حال اجراست؟**

```bash
cd self && python manager_bot.py
```

باید در کنسول `🤖 ربات مدیریت سلف: @username` چاپ شود. اگر خطا داد،
همان خطا متن مشکل است (معمولاً env ناقص).

**۲) ⭐ شایع‌ترین علت: توکن مشترک با سلف قدیمی**

اگر `main.py` (سلف) با **همان توکن ربات** در حال اجراست، تلگرام آپدیت‌های
`/start` را بین دو پروسه پخش می‌کند → بعضی پیام‌ها به سلف می‌رسد (که هندلر
/start ندارد) و ربات مدیریت هیچی نمی‌بیند. دقیقاً همین باعث می‌شود
«کارهای قدیمی سالم باشند ولی ربات مدیریت جواب ندهد».

راه‌حل (یکی از دو تا):

- یا `main.py` قدیمی را **متوقف** کنید،
- یا با @BotFather یک **ربات دوم** بسازید و توکنش را در `MANAGER_BOT_TOKEN`
  بگذارید (پیشنهادی). ربات مدیریت با توکن خودش، و سلف با توکن پنل خودش.

**۳) با کدام ربات چت می‌کنید؟**

ربات مدیریت و ربات پنل سلف دو چیز متفاوت‌اند. باید در همان رباتی که توکنش
را در `MANAGER_BOT_TOKEN`/`BOT_TOKEN` گذاشتید `/start` بفرستید — نه ربات پنل.
یوزرنیم دقیق ربات مدیریت موقع اجرا در کنسول چاپ می‌شود.

**۴) تست رسیدن آپدیت**

وقتی `/start` می‌فرستید، باید در کنسول ربات این خط چاپ شود:
`📩 /start از کاربر ...` — اگر چاپ نشد یعنی آپدیت به این پروسه نمی‌رسد
(مورد ۲ یا ۳). اگر چاپ شد ولی جوابی نیامد، خطای داخلی خودکار هم در کنسول
چاپ و هم داخل چت به شما پیام خطا داده می‌شود.

**۵) ADMIN_ID باید «آیدی عددی» باشد** (نه یوزرنیم) — مثلاً `828898604`.

> نکته: فایل `.env` از پوشه‌ی `self` خوانده می‌شود (مستقل از محل اجرا).

### حالت تک‌کاربره (مثل قبل — بدون تغییر)

```bash
cd self
python main.py      # همان .env قبلی: API_ID / API_HASH / PHONE_NUMBER / BOT_TOKEN
```

این حالت دقیقاً مثل قبل کار می‌کند (سازگاری کامل حفظ شده).

```
├── clock.py / reaction.py / banner.py / effects.py / spam.py / action.py / ...
├── config.json        # کانفیگ تک‌کاربره (در حالت چندکاربره = کانفیگ مدیر)
├── sessions/          # سشن‌ها (gitignore)
├── data/              # دیتابیس + config.json هر کاربر + commands.json (gitignore)
└── logs/              # لاگ سلف هر کاربر (gitignore)
```

## نحوه‌ی کار main.py در حالت چندکاربره

ربات مدیریت برای هر کاربر یک پروسه‌ی `main.py` با متغیرهای محیطی اختصاصی اجرا می‌کند:

| متغیر | معنی |
|---|---|
| `SELF_API_ID` / `SELF_API_HASH` | API کاربر |
| `SELF_SESSION` | مسیر سشن (مثلاً `sessions/u123`) |
| `SELF_BOT_SESSION` | مسیر سشن ربات پنل کاربر |
| `SELF_CONFIG` | مسیر config.json کاربر |
| `SELF_BOT_TOKEN` | توکن ربات پنل اختصاصی (اگر باشد، پنل مشترک استفاده نمی‌شود) |
| `SELF_PANEL_BOT` | یوزرنیم ربات مدیریت برای پنل مشترک (خودکار تنظیم می‌شود) |
| `SELF_PHONE` | شماره کاربر |

اگر این متغیرها نباشند، از متغیرهای قدیمی (`API_ID` و ...) استفاده می‌شود.
